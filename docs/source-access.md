# Source access at the foundation milestone

Stage 2 adds two local sources: the user-selected public page in Chrome and the public-suffix data bundled in pinned `tldts@7.4.19` (including private hosting suffixes). Goal matching uses a local, bounded vocabulary; there is no external intent call. Current and suggested addresses are checked without fetching destinations or transmitting page contents. Neither public workflow needs the optional API service. The six remote provider interfaces below remain separate and unverified.

Checked November 6, 2026 (America/New_York). No live review, offer, model or threat result was obtained. The six server configuration flags were absent in the builder environment; no credential values were read out or requested. The API has **no live connectors**. Supplying a key by itself changes readiness to “connector unavailable,” never to “ready.”

Two early requests tested actual anonymous access from the build environment. A GET to Trustpilot’s business-unit lookup for the public example domain returned HTTP **403** and an HTML error. A GET to eBay Browse item-summary search for “notebook” (limit one) also returned HTTP **403** and HTML. Neither was a verified sample result. These responses establish what this environment received; they do not establish why access was denied, or what an entitled account would receive.

Ownership of each external connection is unassigned. Before marking any one live: confirm permitted access, verify identity with an authorized successful sample, document coverage/cost/quota, and exercise the normalization and failure paths. No third-party site was scraped, no accounts were created and no purchases were made.

The service binds to `127.0.0.1:4317`. `GET /health` exposes readiness booleans, never secrets. `POST /v1/lookup` accepts a strict provider/subject pair; missing connectors return HTTP 503 with an unavailable report and no evidence. A website-identity report, a website-risk report, seller feedback and product feedback have different subject types. The extension calls only the fixed health URL when the user asks to check the local service.

Server policies: JSON input up to 2 KiB, 90 requests/minute per local service, a 3.5-second upstream deadline and cancellation on disconnect. At most 64 successful normalized responses may be cached, for at most 60 seconds and never past evidence expiry; unavailable and malformed results are not cached. Future connectors must contain their own fixed upstream endpoint and may not use page content to select it. This loopback service is not a publicly authenticated API.
